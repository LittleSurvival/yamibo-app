# AppSync v3 合成資料與儲存量測基準

更新日期：2026-09-17。

## 可重現的合成資料

`AppSyncSyntheticCorpus` 完全以固定常數產生資料，不讀取使用者匯出檔、帳號、
裝置、系統時間或網路。資料涵蓋 19 個領域、5 種操作、設定、解析後狀態及檢查點。
操作歷程包含閱讀進度更新、關聯移除後重加，以及留下刪除標記的暫存筆記。
最終有效資料與快照一致；刪除標記則保留於解析後狀態。

| 規模 | 收藏數 | 閱讀紀錄數 | 筆記 UTF-8 位元組數 |
| --- | ---: | ---: | ---: |
| Small | 8 | 12 | 256 |
| Typical | 300 | 600 | 8,192 |
| Oversized | 5,000 | 10,000 | 131,072 |

所有規模均驗證資料生成與領域覆蓋；Small 另驗證型別正規化、亂序與重複重播、
v2 日誌／檢查點往返及可重現編碼。v2 關聯移除仍保留既有契約要求的識別欄位；
這不表示 v3 的空操作主體及結構化識別碼轉接已完成。

## 歷史格式回歸案例

`AppSyncLegacyPayloadRegressionTest` 以合成資料手動組成 v1 JSON 與 v2 gzip/Base64
封套，刻意繞過目前寫入端的過濾，重現舊版可能留下的資料。日誌案例包含未宣告設定
與未知實體欄位；檢查點案例包含快照封面、解析後欄位封面、每個勝出操作內的封面
副本，以及重複識別欄位、父層標籤與完整操作內容。

讀取端先驗證原始指紋並保留來源資料，供後續修復與覆蓋證明使用。狀態合併及新
檢查點建構則排除未知值與封面；直接將未過濾的舊檢查點交給目前寫入器會被拒絕。
測試同時確認來源物件未被原地修改。這些案例並不表示既有持久化主體已完成清理，
也不表示 v2 的識別欄位、父層標籤及操作副本已完成去重。

2026-09-18 修正合成語料的暫存筆記 identity 分隔符，使其符合正式產生端，再重跑上述數值。
Canonical checkpoint 原始區塊為 5,371 bytes，57 個 unique winning operations 支援 331 個

`peakMemoryBytes=null` 與 `deviceProfile=unmeasured` 明確表示未完成裝置量測。

## SQLite 與遠端空間分開計算

`AppSyncStorageAccountingFixture` 使用獨立的記憶體 SQLite 與正式資料表結構，
建立有效主體、超過 1 MiB 的已取代主體、無主體的操作收據，以及兩份假遠端封套。
欄位大小使用 `length(CAST(fieldsJson AS BLOB))` 計算 UTF-8 位元組，避免中文字元數
被誤當成位元組數。這項數值僅計算欄位主體，不代表索引、因果資料或整列的儲存成本。

測試分別驗證：

- 標記為已取代不等於刪除主體，也不能宣稱已回收空間。
- 刪除主體會增加 `freelist_count × page_size`，但不立即減少配置頁面。
- 僅在測試資料庫執行的 `VACUUM` 會減少 `page_count × page_size`。
- 本機操作不會改變假遠端封套的數量／位元組，遠端移除也不改變本機資料。
- 無主體收據仍有中繼資料及頁面成本，不能把它的整列視為零位元組。

上述測試驗證量測方式，不授權正式環境清理，也不代表覆蓋證明、30 天保留期限、
背景壓縮策略、磁碟檔案縮減或遠端刪除狀態機已完成。

## 重跑與尚待驗收

```powershell
.\gradlew.bat --no-daemon :shared:testDebugUnitTest
.\gradlew.bat --no-daemon :composeApp:testDebugUnitTest --tests '*CloudSyncUiStateTest'
openspec validate appsync-v3-storage-recovery --strict
```

本次 504 個 shared 測試與 15 個 CloudSyncUiState 測試通過。49 個可同步設定均核對
正式設定產生端的型別，並驗證預設值可通過正規化及欄位編碼往返。

任務 1.1、1.6 已完成；1.2 的 Android／iOS 裝置峰值記憶體、實際寫入放大及效能
門檻仍待量測。欄位登錄表與編碼器尚未構成完整 v3 封套、重建與發布流程，不能
據此啟用 v3 寫入或正式清理。
